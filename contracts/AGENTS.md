# Guarded vault contract
## Purpose
Enforce owner/operator isolation and spending limits on-chain for native/token payments, swaps, AAVE positions and CCTP burns.
## Ownership
contracts/, scripts/contracts/, src/contracts/ generated ABI and contract tests. Root owns src/abi.ts facade and shared SDK execution.
## Local Contracts
AgentVault constructor(address owner,address operator,address router,address aavePool,address tokenMessenger,uint32 sourceDomain). securityVersion() returns uint256 1. Owner controls pause, operators, token policy, recipients, swap floors and bridge destinations; operator cannot call owner setters. Standard owner address is explicit, with no fabricated AI-only, NFT or ERC-4337 claims.
Operations: agentExecute(address to,uint256 value,bytes data) accepts empty calldata only; agentTransferToken(address token,address to,uint256 amount); agentSwap(address tokenIn,address tokenOut,uint256 amountIn,uint256 minimumOut,uint24 fee,uint256 deadline); agentSupply(address token,uint256 amount); agentWithdraw(address token,uint256 amount); agentBridge(address token,uint256 amount,uint32 destinationDomain,bytes32 recipient,uint256 maxFee,uint32 minFinalityThreshold). Protocol operations require explicit token policy, fixed verified protocol address and bounded exact approvals, cleared afterward. Swap output and AAVE withdrawals return to the vault; bridge recipient must match owner configuration. No generic operator batching or arbitrary ERC20 approvals.
Views/mutations: setSpendPolicy(token,perTx,periodLimit,periodLength), remainingBudget(token), spendPolicies(token), setOperator(operator,bool), isOperatorActive(operator), setRecipient(recipient,bool), setSwapPair(tokenIn,tokenOut,minRateX18,validUntil), setBridgeDestination(domain,recipient), setPaused(bool), stakingPrincipal(token), getPending(id) includes exact calldata, pendingNonce(), approvePending(id), cancelPending(id), ownerExecute(to,value,data). Queue may support over-budget transfers with owner approval; prohibited targets/calldata must revert.
TransactionExecuted(address indexed target,uint256 value,address indexed executor); TransactionQueued(uint256 indexed txId,address indexed to,uint256 value,address token,uint256 amount); TransactionApproved(uint256 indexed txId); TransactionCancelled(uint256 indexed txId). Verify event names against generated ABI.
## Work Guidance
Use pinned OpenZeppelin SafeERC20/ReentrancyGuard. No unbounded approvals, fee transfers before success, public initialization, upgrade mechanism, owner-less configuration, or constructor deployment from agent keys. Protocol fee defaults zero; do not retain hardcoded fee addresses. Swap requires nonzero owner floor and non-expired deadline; invalid native calldata always rejected. Reentrancy protection and failed-call rollback required. Owner policy changes must not permit pending/operator replay unexpectedly.
## Verification
Write failing contract tests first, compile Solidity deterministically, run an actual local EVM with adversarial mock tokens/routers/pools/messenger. Include unauthorized caller, cap, allowances, reentrancy, zero/invalid amounts, expired trade, malicious recipient, revert rollback and queue contents. Export a deterministic as-const ABI at src/contracts/AgentVaultAbi.ts. Preserve compiler evidence and license notices; contract audit and live deployments remain external release gates.

## Defined v1 behavior and integration contract
The generated ABI identifier is `AgentVaultAbi`. Immutable protocol getters are `router`, `aavePool`, `tokenMessenger`, and `sourceDomain`; configuration accepts zero addresses to disable integrations and otherwise requires deployed code. Deployment verification of protocol implementations and chain-specific addresses is a separate owner/release responsibility.

`spendPolicies(token)` exposes `(perTx,periodLimit,periodLength,windowStart,spent)`; native currency uses address zero. `recipients(address)` is a boolean, `swapPairs(tokenIn,tokenOut)` exposes `(minRateX18,validUntil)` in raw token-unit ratios scaled by 1e18, and `bridgeDestinations(domain)` is the exact bytes32 recipient. Budget windows restart after their configured duration; withdrawals consume their requested amount conservatively, even if the pool returns less.

`getPending(id)` returns the named tuple `(to,value,token,amount,data,createdAt,executed,cancelled,expiresAt,policyEpoch)`. Only otherwise-valid native/token transfers exceeding budget can queue. Calldata is empty for native and exactly ERC20 `transfer(to,amount)` for tokens. Queue expiry is one day. Any owner policy/operator/recipient/pair/bridge/pause change invalidates earlier entries through a global epoch; approval also checks the creating operator remains authorized. Owner approval is an explicit exception to operator limits, never a generic calldata/batch approval.

The configured router uses the SwapRouter02 seven-field `exactInputSingle` tuple without a deadline field; `agentSwap` enforces deadline itself, with a one-hour maximum validity and an owner floor expiry. Fixed AAVE V3 Pool calls always supply/withdraw to this vault. CCTP V2 uses the seven-parameter `depositForBurn`, zero destinationCaller, owner-configured mint recipient, fee strictly below burned amount, and canonical finality thresholds 1000/2000. No SDK protocol fee or collector exists.

## Verification commands and limitations
`node scripts/contracts/compile.mjs` generates the deterministic TypeScript ABI and ignored compiler artifacts. `node --test tests/contracts/AgentVault.test.mjs` compiles adversarial fixtures and executes signed disposable transactions in EthereumJS VM (Cancun), including atomic rollback and allowance assertions. Constructor-only scaffold is used solely for the initial feature-absent red test, then replaced by the guarded implementation.

Local EVM mocks prove the specified contract boundary and state transitions; they do not prove live protocol deployment correctness, oracle quality, cross-chain settlement, token solvency, or immunity to malicious balance reporting. Owners must explicitly allow trustworthy standard ERC20s and verified protocol deployments. Mainnet remains gated by independent contract review/audit and live-chain evidence.

Owner may call the same bounded `agent*` operations for external-wallet console use, but may never be enrolled as an operator. `isOperatorActive(owner)` remains false. Agent gas identities retain only explicitly enrolled operator privileges; owner/admin signatures must never be given to the AI.

## Verified implementation evidence (2026-10-12)
`node scripts/contracts/compile.mjs` succeeds with `0.8.37+commit.f401782d.Emscripten.clang`, optimizer 200, Cancun, and disabled metadata trailer. It generates both `src/contracts/AgentVaultAbi.ts` (65 ABI entries) and `src/contracts/AgentVaultBytecode.ts`. Runtime bytecode is 15,080 bytes; creation bytecode is 15,990 bytes. Compiler artifacts include deployed-bytecode immutable references and are ignored by git.

`node --test tests/contracts/AgentVault.test.mjs` passes 12 tests using actual local-EVM signed transactions. Initial constructor-only implementation produced 8 semantic red failures; native/token/queue guards then passed 5 while missing swap/supply/bridge functions produced 3 specific red failures; adding protocol operations passed 8. A separate nonstandard-token regression failed because a malicious token could debit amount+1; exact vault-debit and recipient-credit checks then passed this case and fee-on-transfer/queued variants. Role checks explicitly compare Unauthorized/Paused error selectors for every operation. Generated exports are checked against two identical compiler runs and required queue/execution event names.

Token transfers, swaps, supply and burns enforce exact vault debit. Direct and queued payments also enforce exact recipient credit, so deflationary, rebasing, or unexpectedly fee-bearing transfer behavior is unsupported. Failed external calls, malicious router results, token/router/recipient reentrancy and failed queue approval roll back budget, balances, principal, allowance and approval state. AAVE partial withdrawal credits actual received assets and reduces principal by that amount while conservatively charging requested budget.

The aggregate SDK suite was also run while root integration was in progress: 109 passed and 6 root-owned `core.security.test.ts` tests failed (reverted receipts, queued IDs, code-hash substitution, provider chain mismatch, gas-signer value isolation and invalid input). Root is responsible for final whole-tree verification; this module does not claim those unfinished changes passed.

Protocol interface references used for ABI verification: [Uniswap Router02 IV3SwapRouter](https://github.com/Uniswap/swap-router-contracts/blob/main/contracts/interfaces/IV3SwapRouter.sol), [AAVE V3 Pool](https://www.aave.com/docs/aave-v3/smart-contracts/pool), [Circle TokenMessengerV2](https://github.com/circlefin/evm-cctp-contracts/blob/master/src/v2/TokenMessengerV2.sol), [Circle CCTP finality](https://developers.circle.com/cctp/references/technical-guide). No independent audit or live-chain deployment/settlement was performed.

The package entry point `npm run test:contracts` is implemented by `scripts/contracts/test.mjs` and passes the same 12-test suite. Tests do not silently regenerate exports: stale committed ABI/bytecode fails the deterministic-output assertion. `stakingPrincipal` accounts for guarded supply/withdraw calls; explicit unrestricted owner recovery calls or owner transfers of position tokens can change the externally observed position without updating that counter, so consumers must compare actual aToken balances as required by the SDK design.
