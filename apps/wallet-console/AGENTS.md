# Wallet console contract

## Purpose

An accessible browser-only interface for the owner to deploy, understand, configure and use guarded AgentVault testnet wallets.

## Ownership

`apps/wallet-console/` only. Root owns the SDK, contracts, generated ABI/bytecode, repository dependencies, CI, integration and shipping. Local UI package/lock/config/tests are owned here. Do not commit, deploy to a live network, publish or edit sibling ownership paths.

## Local Contracts

- React/strict TypeScript/Vite. Connect an injected EIP-1193 wallet only. Never collect private keys, seed phrases or signatures. No backend custody or automatic transactions.
- Overview starts disconnected and displays no synthetic balances. Explicit labelled demo mode is isolated and cannot sign. Demo assets are examples, never live finance.
- Every production write uses generated `src/contracts/AgentVaultAbi.ts`, or the generated creation bytecode for the explicit owner deployment wizard. Bounded payments/trades/Aave/CCTP burns call `agent*`; configuration and approvals call owner methods; destination CCTP receiving calls the destination vault's `ownerExecute` with exactly constructed `receiveMessage` calldata.
- Explicit manifest chain/address/runtime hash/version verification and signer role checks precede execution. Only Base/Ethereum/Arbitrum/OP Sepolia are supported. Mainnet manifests remain rejected; a self-asserted audit flag cannot unlock them.
- Every transaction has a human-readable review, complete calldata, estimated fee, external-wallet signing, simulation and successful receipt checks with two confirmations. Wallet account/network changes invalidate the session review. Owners can call bounded operations; operators cannot call owner methods.
- All wallet broadcasts share `intents.ts`. Before `eth_sendTransaction`, persist a strict whitelisted public intent with original chain, signer, destination, zero wallet value, explicit nonce, calldata digest and public recovery fields. Use an origin-wide Web Lock for atomic journal claims and updates across tabs; unavailable locks/storage fail closed before signing. Persist no raw calldata, creation data, signatures or attestations. Only direct numeric wallet error code 4001 or an established pre-call failure clears an attempted-send gate without receipt evidence; text containing rejection words cannot do so. A provider response lost after broadcast stays unknown across close, navigation, wizard remount and reload. Do not offer deletion or retry of unresolved intents.
- Persist a returned hash before notifying public UI callbacks. Storage or callback failures retain the original id/hash in `IntentSubmissionError` and leave the gate unknown. Recovery must verify the original transaction chain, signer, destination, value, nonce and calldata digest, then the matching two-confirmation receipt with an explicit success/reverted status. Unsupported receipt statuses remain unknown. Mint reconciliation additionally verifies the bound transmitter, nonce consumption and expected vault credit at the receipt block; attestations are read from transaction data into memory only. Export only the public journal metadata. A confirmed receipt permits new reviewed work, never automatic retry.
- Reconciliation commits re-read the latest journal entry inside the origin lock and compare the original immutable identity, known hash, terminal status and existing receipt details. Contradictory stale results must reject while preserving the first saved terminal evidence. Same terminal evidence may be explicitly revalidated.
- `onClaimed` supplies the durably recorded public intent identity before the wallet signing/broadcast await. Each dialog retains that id independently of whether a hash returns. Any original attempt with unknown or terminal receipt evidence spends that review; another tab's successful recovery cannot rearm it. A rejected record establishes no send and permits an explicit retry. Only a fresh review (or fresh deployment wizard) resets the spent authorization; exact original hashes remain available for recovery.
- Provider subscriptions follow the provider captured during explicit connection, including wallets injected after initial render, and remove listeners when that provider changes. Account, chain and disconnect events clear verified balances, role, quotes, reviews and inspected request copies. Async connection, verification/load, quote and request-inspection results must match the active session generation before updating its state. Inspected requests carry chain/vault bindings, render only against that verified deployment and clear on manifest replacement or fresh snapshots. Before owner review, verify that deployment and re-read the selected request so recipient, value, amount and calldata come from its contract.
- Capture the form, every input, provider, session generation, deployment and signer before asynchronous trade/bridge prechecks. Recheck that identity before and after prechecks and simulation; detached or edited forms cannot produce a review. Every submitted vault operation is an immutable `PreparedOperation` bound to chain/vault/runtime hash/signer/provider/calldata digest; `submit` rejects context mismatch before signing or journal creation. Display captured review identities. Receiving drafts additionally retain their original session/source/destination identity.
- The durable journal is the authoritative unresolved-write gate. Public Activity completion updates after verified receipt evidence even if account/disconnect invalidates the view; balances, errors, reviews and busy state retain session guards. Explicit terminal receipt inspection repeats exact transaction/receipt validation and rejects contradictory status evidence without broadcasting again.
- Deployment drafts capture immutable owner, provider and session generation before async checks. Discard late drafts from a changed session; show the captured owner; require the current account to match it; repeat live provider account/network checks immediately before broadcasting creation data from that same owner. Post-deployment verification cannot substitute for this pre-broadcast check.
- App, deployment and recovery reviews share `useReviewDialog`: capture the opener before async simulation can disable it; make the background inert; include enabled visible summary and other tabbable controls; retain container focus with no tabbable controls; preserve busy close protection; restore the opener on dismissal. Do not recreate focus containment just because busy state changes.
- Positive financial amounts use decimal-string-to-bigint parsing with strict precision; no rounding, exponent notation or negative/zero amounts. Quote generation simulates the exact bounded vault swap, applies ceiling for owner pair floor and suggests at most 0.5% slippage. Pending quote results must match the mounted form, every trade input and active session; edits and navigation invalidate displayed quotes. Aave supply/withdraw beneficiaries stay in the vault; actual configured aToken balance and principal are separate, with no assumed APY.
- Latest queue reads retain the recent-50 limit, original ID order and a shared snapshot block. Fetch bounded parallel groups of five; any group failure rejects the snapshot instead of silently omitting requests.
- Source bridge records persist only whitelisted public hashes, addresses, chains, amounts and statuses. Attestations stay in memory. Destination recovery binds original source calldata and the single official MessageSent event, fetches Circle's fixed sandbox HTTPS origin with no credentials/redirects and bounded time/bytes, validates immutable message fields, verifies an explicit destination vault/transmitter hash/domain/owner, checks replay nonce, and confirms consumed nonce and vault credit. Unknown submissions retain their hashes and require receipt inspection before any retry; a confirmed revert permits a newly reviewed attempt.
- Browser manifests may contain only public deployment evidence. Code-hash matching is not an independent audit. Protocol and deployment risks remain visible; never make blanket security or live-settlement claims.

## Work Guidance

Keep dependencies pinned and small. `vite.config.ts` deduplicates browser-safe SDK viem imports. Do not import Node SDK modules (`bridge/client`, file stores, DNS helpers, keys) into the console. `recovery.ts` imports only browser-safe `bridge/message`, `bridge/types` and `bridge/abis`.

Use responsive light/dark styles, labelled keyboard forms, focus-contained review dialogs, a skip link, loading/empty/error states and fixed official explorer origins. Disable unavailable actions with nearby prerequisites. No dead buttons or silent financial fallback. Deployment uses official Base Sepolia protocol addresses and verifies deployed owner/operator/version/protocol configuration before producing the public manifest. Circle test USDC and Aave test USDC are distinct assets.

Public recovery hash links retain their complete text and official explorer destination while wrapping within mobile panels. Do not hide page overflow or truncate hashes to fit a viewport.

## Verification

Run from this directory: `npm run build`, `npm run test:unit`, `npm test`, `npm audit --omit=dev`, `npm audit`. `npm test` selects the locked packaged Chromium fallback on Linux x64 without needing browser CDN downloads or an environment variable; an explicit `PLAYWRIGHT_EXECUTABLE_PATH` can override it. Tests use disposable local-only VM credentials in test utilities, not production hooks.

Browser tests execute real Solidity in EthereumJS VM behind a test EIP-1193 provider. Protocol fixtures are clearly local mocks: these tests establish UI/contract flow, never a live Circle attestation, testnet settlement, independent audit or deployed protocol proof. Root's verification owns fresh aggregate evidence and screenshots. New behavioral changes need observed failing regression coverage before fixes. Tests and render inspection must be performed on a settled tree: editing UI files while Playwright runs triggers Vite HMR and can invalidate evidence.

`tests/injected-wallet.ts` owns the test-only event emitter and provider-request completion barrier; `tests/local-vm.ts` owns deferred computed RPC responses, public wallet transaction capture and multiple real vaults in one VM. Keep these controls out of production. Browser regressions cover each wallet event with an open review and delayed verification/load/quote, late provider injection, delayed connection/request inspection, reverse/forward modal focus and busy/no-tabbable states, plus exact real-VM queued approval/cancellation calldata, explicit signing, one-time recipient credit and owner gating. A two-vault test binds an older queue ID outside the recent window across manifest replacement and an in-flight inspection; deployment tests change owner during deferred review and change the live provider account during final protocol checks without emitting an event.

`tests/intents.spec.ts` executes actual payments, burns, creation and destination receiving whose provider response is deliberately lost after mining. It proves durable unknown gates, exact hash recovery, public-only storage, numeric rejection, unavailable locks/storage, failed hash persistence, throwing public callbacks and unsupported receipts. A concurrent-tab test holds the actual origin lock, observes both claims waiting with no write, then permits exactly one transaction. Delayed quote tests change amount/token/fee/expiry/minimum or navigate away; the queue concurrency test checks the actual 50-request limit, ordered IDs, shared block and maximum five outstanding reads.

Journal race tests hold a computed contradictory receipt until a second reconciler commits the actual mined result, then require the stale result to reject without altering original identity/hash/status or recipient credit. Cross-tab recovery tests leave the original payment/creation/receiving dialog open, resolve its hash elsewhere and attempt its original button again; actual writes must remain one payment/creation or one burn plus one mint. Lock tests do not assume which tab wins.

The recovery layout regression seeds a valid public unknown intent with a known transaction hash, without an injected wallet. At 390px and 1440px it checks document width, the complete hash link and official explorer URL, plus the recovered-hash input value and on-screen link fragments.

`tests/context.spec.ts` defers trade/bridge form prechecks while replacing a verified vault or changing its amount; compatible real VM vaults prove discarded stale reviews and fresh writes to the captured target. It exercises account/disconnect during deferred receipt completion followed by terminal receipt revalidation and a new review. Direct prepared vault/signer/chain mismatch cases must create neither a journal record nor an actual wallet transaction.
